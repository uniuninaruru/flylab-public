### Edge direction, end to end on real rows

1. **Code path.**
   - `body_pre` → `_lookup` → `pi` → `src` (`malecns.py:126,129,139`);
   - `body_post` → `qi` → `dst` (`:127,130,140`);
   - `build_graph_indexed` sorts by `(src, dst)` without swapping (`graph.py:323-324`);
   - `write_processed` writes `src_idx`/`dst_idx` from `graph.src`/`graph.dst` (`processed.py:58-66`).
2. **Real-row test.** Every 10th batch of the official weights file (232 batches, 15,204,352
   rows) was run through `flylab data prepare` + `verify` with the real annotation and transmitter
   files. `verify` passed for all three node sets. The independent biological priors below would
   all invert if `src` were postsynaptic:

| Check (default node set) | as `src` | as `dst` | Ratio |
|---|---|---|---|
| synapses touching motor neurons (`vnc_motor`, `cb_motor`; their output is mostly outside the CNS) | 19,016 | 1,028,518 | 54× more as target |
| synapses touching sensory neurons (`*_sensory`) | 820,820 | 205,316 | 4.0× more as source |
| `R1-R6` → `L1/L2/L3` vs reverse | 13,078 | 793 | 16.5× |

This verifies the direction of the processed graph, which is what FlyLab controls. That
`body_pre` means presynaptic in the upstream file is inferred from the column names and these
priors, not from upstream documentation (the download page was unreachable).

### Sparse graph semantics and integer limits (PASS)

- **Duplicates:** `DuplicateRule.ERROR` is the default and `prepare` uses it. The sample had 0
  duplicate pairs (`n_input_rows == n_unique_edges`).
- **Self-loops:** kept and counted (8 in the sample's kept edges).
- **Isolated neurons:** counted.
- **Sort order:** `np.lexsort((dst, src))`, primary key `src`. `verify` checks the strictly
  increasing key `src·N + dst` in `int64`; its maximum is about 2.8e10.
- **CSR `row_ptr`:** `int64`, length N+1, from `bincount(src)`. Tested on the hand fixture.
- **Limits:**
  - N = 166,700 ≪ 2³¹; input rows 151,856,684 < 2³¹−1 (positions are `int64` anyway);
  - max weight 2,591 fits `int32`; synapse totals are `int64`;
  - `signed_count` is `float32` and exact for integers up to 2²⁴.
- **Dense N×N:** refused above 4,096 neurons.

### Memory (estimate from code + measurement on real rows)

`tracemalloc` per stage on the LZ4 sample (`upstream_checks.py memory`):

- `stream_edges` peaks at **429 MB** while holding only 42 MB of kept rows (2,582,969).
  - The peak comes from `seen`, the set of every body id in the file. It is used only for the
    `bodies_in_weights` statistic.
  - Its size scales with distinct bodies: 11.9 M in the sample, at most 88.4 M in the full file.
- `build_graph_indexed` uses **59.4 B per kept row**. The caller keeps its unsorted arrays alive
  during the sort.

Full-file estimate (not a measurement):
- kept rows ≈ 25.8 M, so the build needs ≈ 1.5 GB;
- `seen` transient ≈ 0.4–2.8 GB;
- **process peak ≈ 2–4 GB**, which fits the 15 GiB WSL VM.

The host's real `manifest["peak_rss_bytes"]` should replace this estimate. The low-severity
finding is that the M1 "low-memory pipeline tested" gate has no test (#11).

**Correction (after the owner's real run, see the Addendum).**
- The kept-row estimate was close: 25,582,938 measured vs 25.8 M estimated, about 1% off.
- The peak estimate was wrong: `docs/acceptance/M1.md` reports **7.73 GiB peak RSS and 1,247 s**
  for the audited revision `67dc887`, about twice my upper bound.
- tracemalloc sees only NumPy allocations. It misses Arrow decompression buffers and allocator
  retention, which this estimate did not include.
- At 7.73 GiB on a 15 GiB VM shared with other services, #11 was worth more than "Low".
- `c29d70c` makes the all-segment count opt-in. The owner measured 2.22 GiB
  (`peak_rss_bytes` 2,381,185,024 in the committed manifest) and 5.8 s of streaming.

### Fetch safety (PASS)

- Only names registered in `sources.py` can be fetched. `KeyError` is raised otherwise, and a
  path-traversal name is tested.
- Bytes stream to `<name>.part`, which is deleted on any exception (`BaseException`, including
  Ctrl-C) and then atomically renamed.
- `Content-Length`, final size and base64 MD5 are compared with the registry. A corrupted local
  copy is replaced.
- `SOURCE.json` is written atomically and records no host paths.

Notes (not filed):
- SHA-256 is recorded but has no expected value. MD5 against the registry is the only upstream
  check; MD5 second preimages are not practical, so this is acceptable.
- `urllib` follows redirects without restricting the scheme. Integrity still rests on MD5.
- `SOURCE.json` is written only after every requested file succeeds (see #5).

### Scripts and containers

- **Redaction (#7).** All leaks were reproduced by running the code; the `.ps1` block ran under
  PowerShell 7.4.6. The committed evidence of 2026-11-04 contains no address or name.
  - an IPv4 address followed by `.`;
  - IPv4-mapped IPv6 (`[::ffff:a.b.c.d]` keeps the last three octets);
  - any line containing `version`, including inside `conversion`;
  - an address followed by `-word`;
  - user or host names shorter than 3 characters.
- **Remote scripts (PASS, by reading; not executed: no host).**
  - Every remote command is UTF-16LE base64 in `powershell -EncodedCommand`.
  - WSL scripts are base64 again inside a single-quoted PowerShell string.
  - Distro, user and service names are allowlisted (`[A-Za-z0-9._-]`, `[a-z0-9-]`).
  - Extra `compose_run.sh` arguments are quoted with `printf %q`.
  - `sync_to_host.sh` resolves the ref to a commit SHA before use.
  - `BatchMode=yes` throughout.

  No injection path was found.
- **Containers (PASS + #12).** `cap_drop: [ALL]`, `no-new-privileges`, `network_mode: none`
  (except `data-fetch`), non-root `ubuntu`, read-only data mounts, digest-pinned bases, no socket
  or host network. Missing: memory and PID limits on a VM shared with the host's other services.

Notes (not filed):
- `sync_to_host.sh:43` deletes everything in `~/flylab` except `artifacts/` and `data/`. That
  includes a host-side `.env` (e.g. a neuPrint token), which `.env.example` suggests keeping there.
- The repository commits the GPU host's WSL account and distro names and the SSH alias (in
  `CLAUDE.md`, `README.md`, `docs/`, `scripts/remote/common.sh`). `SECURITY.md` and `CLAUDE.md`
  say user names are never committed. This looks like a deliberate owner decision for a generic
  name, but the rule and the practice disagree; the owner should pick one.
